# 2.5 上下文分层压缩与防腐烂策略

> **本节要点**：理解为什么即使上下文窗口足够大，依然必须进行压缩；掌握“上下文腐烂 (Context Rot)”与“上下文焦虑 (Context Anxiety)”的底层机理；透视 Experiment 2-10 六大压缩策略对比与 Claude Code 生产级五层压缩漏斗；掌握终极优化模式——“以隔离代替压缩 (Sub-Agent Context Isolation)”。

---

## 1. 为什么压缩不仅是长度问题？三大驱动力

很多开发者误以为：只要云厂商把上下文窗口开放到 200 万 Token（2M），我们就不需要做上下文压缩了。这是极其危险的误解！

```mermaid
graph TD
    subgraph Drivers["上下文压缩的三大深层动机"]
        D1["1. 成本与延迟约束 (Cost & Latency)<br/>Token 越多计费越贵，Prefill 耗时越长，TTFT 严重劣化"]
        D2["2. 提升推理质量 (Reasoning Quality)<br/>提炼后的高信息密度结构，推理表现远好于在海量垃圾中搜索"]
        D3["3. 缓解模型的上下文焦虑 (Context Anxiety)<br/>当感知到窗口接近枯竭时，模型会慌乱抢先收尾、潦草交差"]
    end
```

### Context Overflow（溢出） vs Context Rot（上下文腐烂）
*   **Context Overflow (溢出)**：超出了物理 Token 上限，系统直接返回 400 报错崩溃。这是显性错误。
*   **Context Rot (上下文腐烂)**：**装得下，但找不到了**。随着无用工具输出（如几千行未筛选的 HTML）充满窗口，注意力被严重稀释，模型原本敏锐的推理与规范遵循能力悄然衰退，陷入原地打转。这是隐性致命慢性病。

## 2. 六大压缩策略实战量化对比 (Experiment 2-10)

《AI Agents in Depth》通过“追踪 OpenAI 联合创始人去向”的长程调研任务，测试了 6 种压缩方案：

```mermaid
graph TD
    subgraph Strategies["六大压缩策略演进"]
        S1["① 不压缩 (No Compression) ──► 5 轮直接爆掉 128K 窗口，任务失败 ✗"]
        S2["② 单独摘要 (Individual) ──► 各段独立摘要，信息碎片化严重，耗费 276K tokens"]
        S3["③ 合并摘要 (Combined) ──► 全量拼合压缩，长输入截断丢失尾部信息"]
        S4["④ 上下文感知压缩 (Context-Aware) ──► 结合当前 Query 目标精准提炼，Token 暴降 76%! ★"]
        S5["④+⑤ 感知+引用 (With Citations) ──► 提炼事实并附带来源 URL，保留可回溯无损索引"]
        S6["⑥ 自适应窗口 (Adaptive Window) ──► 达到 80% 软阈值前全量保留，超限批量压缩"]
    end
```

> 🏆 **核心技术突破：Context-Aware Compression（上下文感知压缩）**  
> 压缩不是简单地让模型对大段文字做无目的概括。在压缩 Prompt 中明确传入：  
> `当前搜索目标是：{query}` 以及 `当前已知事实是：{context}`。  
> 模型便能精准剔除噪声，将 15 万字符压缩为 2000 字符，同时**百分之百保留后续决策所需的核心人名与职务变动**！

## 3. 生产级五层阶梯压缩漏斗 (Claude Code 实践)

```mermaid
flowchart TD
    In[工具输出产生] --> L1{第 1 层: 工具输出预算控制}
    L1 -->|超过阈值| D1[截取首尾各 50 行，完整结果存磁盘]
    L1 -->|正常大小| L2{第 2 层: 确定性无用噪声删除}
    D1 --> L2
    L2 -->|无价值噪声| D2[直接丢弃，不消耗摘要 Token]
    L2 -->|有效轨迹| L3{第 3 层: API 级微压缩}
    D2 --> L3
    L3 -->|即将溢出| D3[通知服务端删除历史超大 tool 结果]
    L3 -->|安全水位| L4{第 4 层: Git Log 式归档摘要}
    D3 --> L4
    L4 -->|长程任务| D4[每轮独立提炼工作备忘，保留因果链]
    L4 -->|极端情况| L5{第 5 层: 全量压缩与熔断保护}
    D4 --> L5
    L5 -->|连续 3 次失败| Exit[触发熔断器，安全退出移交人工]
```

## 4. 终极范式：以隔离代替压缩 (Sub-Agent Context Isolation)

压缩是信息已经进入上下文后、不得不付出的“有损补救措施”。
**更高级的系统架构，是在噪音进入主上下文之前就将其彻底隔绝！**

```mermaid
graph TD
    subgraph Naive["单 Agent 模式：主上下文迅速污染"]
        Main1[Main Agent] -->|自己逐个翻找代码库| Files["几十个文件、上万行代码涌入主窗口！"]
        Files -->|造成 Context Rot| Main1
    end

    subgraph Isolated["Sub-Agent 上下文隔离模式：主干极致精简"]
        Main2[Main Agent] -->|下发自包含子任务| Sub["代码检索专用 Sub-Agent"]
        Sub -->|在私有独立沙箱完成海量探索| Temp["几万 Token 原始代码在子进程丢弃"]
        Sub -->|仅返回 200 字结构化结论| Main2
    end
```

*   **工程成效**：主 Agent 的上下文只有一进一出两条干净消息，**前缀 KV Cache 毫发无损**，探索过程中的成千上万行代码垃圾随 Sub-Agent 的销毁而直接释放。
